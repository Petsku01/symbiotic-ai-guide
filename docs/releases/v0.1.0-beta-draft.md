# v0.1.0-beta (Draft)

Status: Draft release framing for the first public beta.

## Guarantees (beta scope)

- Documented onboarding path is maintained in `docs/getting-started/GOLDEN-PATH.md`.
- Safety/doc drift checks are provided via:
  - `./scripts/validate-docs-safety.sh`
  - `./scripts/smoke-test-onboarding-commands.sh`
- Core docs remain explicit about validation scope and known unknowns.

## Beta limitations

- This repository reflects a single-partnership case study, not a generalized benchmark.
- Validation is primarily non-destructive command/documentation alignment.
- Platform/runtime behavior may vary by host OS and OpenClaw version.
- Some guides are intentionally conservative and may not cover all advanced production needs.

## Known risks

- Command drift risk as OpenClaw CLI evolves.
- Environment-specific setup differences (Linux/WSL/macOS) can cause onboarding variance.
- Legacy script references may still exist in external/private automation environments.
- Documentation confidence can lag behind fast operational changes without strict status sync.

## Upgrade notes

From pre-beta docs state to `v0.1.0-beta` framing:

1. Follow `docs/getting-started/GOLDEN-PATH.md` for first-run setup.
2. Re-run both validation scripts locally after pulling latest docs.
3. If you use automation scripts, migrate to `*-improved.sh` variants per `tools/automation/README.md`.
4. Treat non-improved automation scripts as legacy pending removal per deprecation policy.

## RC gate reference

- Required release gate: `docs/releases/RC-GATE-CHECKLIST.md`

## Exit criteria toward stable release (preview)

- Repeatable validation runs published under `docs/validation-runs/`.
- Reduced onboarding drift incidents.
- Clear migration completion for legacy automation script users.
